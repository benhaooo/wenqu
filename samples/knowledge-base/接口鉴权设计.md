# 接口鉴权设计

## 总体方案

后端接口使用 JWT 鉴权，分为 Access Token 和 Refresh Token 两种令牌。登录成功后，后端同时签发两种令牌。

## Access Token

Access Token 有效期 2 小时，使用 HS256 签名，只保存在前端内存中，不写入 localStorage，刷新页面后需要重新换取。每个请求在 `Authorization: Bearer <token>` 请求头中携带。

## Refresh Token

Refresh Token 有效期 7 天，通过 httpOnly Cookie 下发，Cookie 属性为 `SameSite=Strict`，路径限定为 `/api/auth`，前端脚本无法读取，防止被 XSS 窃取。

每次刷新都会轮换：旧的 Refresh Token 立即失效并签发新的。如果检测到已经失效的 Refresh Token 被再次使用，说明令牌可能泄露，后端会吊销该用户这一登录链上的全部令牌，用户需要重新登录。

## 退出登录

退出时后端删除 Refresh Token 记录并清除 Cookie，前端清空内存中的 Access Token。
