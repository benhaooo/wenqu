# 文档规范

## 文档分类

| 类别 | 位置 | 回答的问题 |
|---|---|---|
| 规则入口 | `CLAUDE.md` | AI 开发时必须遵守什么 |
| 项目入口 | `README.md` | 这是什么、怎么跑起来、演示账号 |
| 现状文档 | `docs/architecture.md`、`docs/modules/`、`docs/conventions/`、`docs/evaluation.md` | 现在是什么 |
| 决策记录 | `docs/_decisions/` | 为什么这样 |
| 个人笔记 | `docs/_notes/` | 学习笔记与面试素材，不约束代码 |

变化过程由 Git 历史记录，不写进任何文档。待办和计划不写进仓库文档。

## 现状文档

- 只用陈述句描述当前实现。不出现描述变化或计划的词：「原来」「改为」「新增」「不再」「暂时」「后续会」「将来」「计划」「TODO」。
- 设计改变时直接重写对应段落，不追加「更新」段落。
- 每个事实只在一处定义，其他地方用链接引用。例如模块依赖方向只在 `architecture.md` 定义。
- 代码和文档在同一次提交中修改。二者不一致视为缺陷。

## 模块文档

每个后端模块一份 `docs/modules/<模块>.md`，使用 [模块文档模板](../modules/_template.md)，包含五节：职责、数据模型、对外接口、核心流程、依赖。前端 feature 的说明写在对应后端模块文档的「对外接口」或「核心流程」中，不单独成文。

## 决策记录

- 每条一个文件：`docs/_decisions/NNNN-标题.md`，编号四位、递增，使用 [决策记录模板](../_decisions/_template.md)。
- 包含四部分：背景、备选方案、决定、代价。
- 写完后不再修改。被推翻时，只在旧记录顶部加一行 `> 已被 [NNNN](NNNN-标题.md) 取代`，并新写一条。
- 需要写决策记录的情况：选型、架构调整、偏离需求文档的约定、有明显代价的取舍。

## 格式

- Markdown，标题从 `#` 开始逐级使用。
- 图用 Mermaid，放在文档内，不使用图片文件。
- 链接使用相对路径。
