# 0010 文本块在文档彻底删除时清理

- 日期：2026-10-10
- 状态：已采纳

## 背景

文档删除后必须立即不再出现在 AI 回答中（1.5 验收）。删除先进入回收站，30 天内可以恢复。[0006](0006-跨模块事件使用事务性发件箱.md) 中设想的是文档删除后通过事件删除文本块，检索时再按有效文档过滤一次，弥补事件投递的延迟。

## 备选方案

1. **移入回收站时删除文本块，恢复时重新索引**：回收站中的文档不占用向量存储；但恢复需要重新调用 Embedding 模型，删除和恢复都要发布事件，恢复后到索引完成之间文档检索不到。
2. **移入回收站时保留文本块，彻底删除时清理**：检索本来就按 document 模块提供的未删除文档过滤，移入回收站立即生效；恢复后无需任何处理。只有回收站清理（彻底删除）发布事件。

## 决定

采用方案 2：

- 移入回收站、恢复不发布事件；检索范围由 document 的 `findActiveDocumentIds` 确定，chat 用 `findActiveDocuments` 再过滤一次检索结果。
- 回收站清理时在同一事务中发布 `document.purged`，retrieval 删除文本块，ingestion 删除索引任务与原文件。

## 代价

- 回收站中文档的文本块继续占用存储，最多 30 天。
- 正确性依赖所有检索调用方都传入未删除文档的范围。retrieval 不自行判断文档状态，这一约束写在 `RetrievalApi.search` 的契约中。
