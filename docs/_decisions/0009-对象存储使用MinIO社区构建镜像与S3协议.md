# 0009 对象存储使用 MinIO 社区构建镜像与 S3 协议

- 日期：2026-10-10
- 状态：已采纳

## 背景

需求文档指定 MinIO 作为文件存储。MinIO 官方已停止发布社区版二进制和镜像，Docker Hub 上的 `minio/minio` 已无法拉取。后端还需要选择访问对象存储的客户端。

## 备选方案

镜像：

1. **`pgsty/minio`**：社区按 MinIO 开源代码持续构建的镜像，配置、行为与 MinIO 一致。
2. **换用其他 S3 兼容实现**（RustFS、SeaweedFS、Garage）：同样可用，但偏离需求文档，各自有兼容性差异。
3. **自行从源码构建 MinIO 镜像**：可控，但增加维护负担。

客户端：

1. **AWS SDK for Java v2（S3）**：标准 S3 协议，任何 S3 兼容存储都能使用；签名链接支持完善。
2. **minio-java**：API 简洁，但绑定 MinIO。

## 决定

- 本地与测试环境使用 `pgsty/minio`，固定到具体版本标签。
- 后端使用 AWS SDK v2 的 `S3Client`，以 path-style 访问，不依赖 MinIO 专有 API。

## 代价

- 依赖第三方社区维护的镜像，需要关注其更新和安全修复；停止维护时换用其他 S3 兼容实现，后端只需修改配置。
- AWS SDK 体积较大，已排除未使用的 Netty 客户端。
